ACCEPTANCE TEST (ADR 0058), run once after training, no retries
- Tool: proyecto/phase2_acceptance.py at 5241c2a (it records its own source SHA-256 and refuses to run with uncommitted changes), built test-first and reviewed before training starts, frozen afterwards; tests use synthetic fixtures only, never acceptance seeds.
- Candidate: the run 2 reigning champion in champions/phase2-run2/ (weights + sidecar), played with temperature 0.05, profile prior 5, adaptation on. Baseline: run 1 gen28, champions/phase2/reigning_champion.pt (tensors identical to run1-g28), temperature 0.05, prior 5, adaptation on. Held-out opponents: phase 1 NetworkPolicy with encoder v1 and its native softmax and profile semantics, as the trainer's phase 1 path loads them. Every network file is hashed before playing; hashes are written to the output.
- Part A, direct: candidate vs baseline on validation_schedule(60001, None, 1000), partition 0, mirror pairs (each deal played twice with seats swapped).
- Part B, held-out: candidate and baseline each play the same validation_schedule(60002, None, 1000) mirror pairs, partition 0, against each held-out network.
- Protocol: both matches start at 0-0; every match starts with fresh policies, fresh RNGs and fresh opponent profiles on both sides (no profile carried from the first match of a pair to the second; the existing mirror helpers that keep profiles across a pair are not reused as is). Action seeds: SeedSequence([schedule_seed, pair_index, match_in_pair, seat]), identical for candidate and baseline, where match_in_pair 0 has the evaluated network in seat 0 and match_in_pair 1 in seat 1.
- Statistics:
  - pair score = (wins of the evaluated network in the two matches) / 2, so 0, 0.5 or 1.
  - Part A: mean of the 1,000 candidate pair scores; 95% interval = mean +/- 1.96 * SD / sqrt(1000), SD = sample standard deviation.
  - Part B: for each pair index i, d_i = mean over the two held-out networks of (candidate pair score - baseline pair score). 95% interval = mean(d) +/- 1.96 * SD(d) / sqrt(1000) (clustered by pair index, equal weight per held-out network). Each held-out network's individual difference and interval are also reported, descriptively.
  - All differences are fractions: "-3 points" means -0.03.
- Decision: run 2 SHIPS (replaces gen28 in champions/phase2/ and the game) only if BOTH: Part A lower bound > 0.50 AND Part B lower bound > -0.03. A bound exactly equal to the threshold fails. Otherwise gen28 stays, and the result is reported as:
  - "regression" if the whole Part A interval is below 0.50 or the whole Part B interval is below -0.03;
  - otherwise "inconclusive (not shown better)".
  This is a one-time shipping acceptance test, not an unbiased estimate of run 2's strength.
- Command (from the repo root, once, after training):
  python proyecto/phase2_acceptance.py --candidate champions/phase2-run2/reigning_champion.pt --baseline champions/phase2/reigning_champion.pt --run-dir training_output/phase2-run2 --held-out-manifest experiments/phase2-run2/held-out.json --direct-seed 60001 --held-out-seed 60002 --pairs 1000 --workers 12 --output experiments/phase2-run2/acceptance

If the test is interrupted, only the missing pairs are played deterministically; no reselection and no threshold change.
