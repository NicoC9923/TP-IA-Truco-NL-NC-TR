# Phase 2 card evidence and validation sampling

Status: accepted. This supplements ADR 0040.

Each learner decision stores the acting player's original card IDs, the opponent's exposed card IDs, and the exact envido constraint as a declared value or an upper bound. The label is the opponent's original three-card hand, obtained from the simulation deal even when the hand ends in a fold; it is not part of the observation or the opponent profile. The learner rebuilds masks against one precomputed table of all 9,880 hands and their tantos, avoiding a separate 9,880-element mask per sample. Exact inference and the learned output use the same public evidence semantics.

Each generation compares exact uniform, bluff-rate-weighted and learned distributions on the same deterministic validation situations. A fixed seeded phase 2 policy replays the first validation deals, retaining at most eight evenly spaced decisions per match until 400 situations are collected; the configurable count is stored in the checkpoint configuration. This fixed policy and its measured opponent profile keep the situations independent of the model being evaluated, while sampling several deals limits dependence on one match. Log loss scores the true original combination. Accuracy is the fraction of still-hidden true cards among the top N hidden-card marginals, where N is the number still hidden; exposed cards do not count. The logged standard error is the sample standard deviation of situation accuracies divided by the square root of the situation count; it is null when fewer than two situations are available. Decisions within a match are correlated, so this descriptive uncertainty can be optimistic.

On this machine, 400 situations with a 15-point validation target took 14.749 seconds including first replay and 8.256 seconds with the fixed situations cached. A tiny 12-worker, 12-match, one-generation run to one point took 5.195 seconds without the head and 15.570 seconds with the head and its 400-situation log; a separate target-one validation measurement was 10.114 seconds cold and 7.855 seconds cached, so the remaining training overhead is too small to estimate reliably from one startup-heavy run. These timings do not establish the fraction of an actual training run spent in checks. The measuring run must verify that fraction and may adjust the situation count or generation size.
