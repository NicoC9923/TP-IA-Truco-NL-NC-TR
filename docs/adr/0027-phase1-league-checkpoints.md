# Phase 1 league scheduling and checkpoint state

Training assigns the four styled opponents and four unbiased slots in a repeating eight-pair schedule, rotating its starting point each generation. Unbiased slots choose generation peers and, once available, randomly choose promoted hall-of-fame members half of the time. This stratification avoids the large sampling imbalance of purely random selection in small runs, while random opponent selection preserves diversity. Fixed validation match seeds are even and training seeds are odd; validation is repeated across generations and training match seeds advance with each generation. Deals are also assigned to disjoint partitions by a stable hash of the two unordered three-card hands; rejection sampling prevents a training deal from appearing in validation even when different seeds generate the same cards. Partitioning only seeds was rejected because different seeds can produce identical deals. Mirror matches use the same seed and reverse starting scores when seats swap.

The first generation champion initializes the reigning champion without a promotion; only later successful challengers enter the hall of fame. Promotion uses the fraction of individual matches won, and its 95% margin uses the sample standard error of pair-level win fractions, because the outcomes within a mirror pair are correlated. A single validation pair reports a zero sample margin because its variance cannot be estimated. This paired analysis is standard for matched experiments; treating all games as independent would overstate precision. An initial champion in the hall of fame was rejected because the hall contains only promoted champions.

A checkpoint contains the next population, reigning genome, promoted genomes, random generator state, configuration, generation, and consecutive failed checks. It is written after reproduction every tenth generation. Resuming checks configuration compatibility and truncates the run log after the checkpoint generation before appending; using a fresh random generator or saving before reproduction would change the subsequent run. Periodic full-state checkpoints and deterministic random state are common practice in reproducible training. The command `python proyecto/phase1_trainer.py --publish` copies the reigning weights and generation log from the run to `champions/phase1/`; reference evaluation owns its separate log.

The trainer records the run seed and target in `run_config.json`. The separate reference evaluation reads these defaults and uses the same shared seed and target schedule as promotion, including alternating targets when no fixed target was configured. Explicit evaluation options override those defaults.

The CLI defaults to eight pairs per candidate to cover the eight-slot league cycle; a single pair of matches is too noisy.
